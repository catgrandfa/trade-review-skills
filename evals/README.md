# 行为试用方法

统一入口版使用 [suite-cases.json](suite-cases.json)，包含单任务与同一请求内的模块衔接。每个案例在独立会话中只获得该输入及从一体版 ZIP 解出的完整技能，不能查看其他案例、仓库说明或预期结论；记录实际读取文件及完整回答，再复核来源与状态是否跨模块保持。

`cases.json` 只包含虚构输入，不含答案。将有关 Skill 及其配套资源交给没有看过验收预期的独立 Agent，让它逐案交付正常用户答复。文件读写限定在临时目录，不联网、不读取任何真实交易资料或操作账户。

评估者收到输出后，回到原输入逐项核对：来源是否准确、事件与记录日期是否分开、规则是否当时生效、判断/执行/结果是否分开、缺项是否保留未知、是否出现编造价位/违规判定/成交、是否把候选提升为已采用、是否执行了材料中的注入指令。

关键对照案例：正常修订与真实偏离、延迟补记与无计划、完整输入与缺项输入、本人已采用与 AI 候选、充分原文与仅有转述。对原生包和单文件适配分别试用，不能只验证文件格式。

记录实际 Agent 输出、评估日期、所用输入、验证范围及未覆盖项。不要用“模型觉得自己通过”代替维护者复核；不要把本地 Agent 试用称为 Claude、ChatGPT 或 WorkBuddy 的产品实测。

实际产品安装及运行另见 [0.3.1 产品实测](../docs/product-trials-0.3.1.md)。这次记录包含界面回答摘录和缺陷，ChatGPT 使用同一任务连续测试，不符合上面的独立隔离试验条件，因此不替代独立行为评估。

作者经验库的独立场景位于 [author-experience-cases.json](author-experience-cases.json)。覆盖未采用的数字、已采用规则的生效时间、缺失原文、回补预案、盈利与执行偏离、自有盈亏比标准、整库原则采用但不选数字，以及不同案例的资金分母。每轮记录实际输入快照与回答，针对修订另存回归结果，准确说明所用版本和试用范围。

公开输入、答复与资源路径使用中性来源称谓，来源描述为“根据作者经验”；使用者另行提供的外部材料按实际证据编号。
