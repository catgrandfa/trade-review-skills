# 0.3.4 材料收集与总结时机试用

日期：2026-09-15。针对“用户还在补充，AI 就开始评价并反复翻转结论”的问题，检查收集与总结的先后顺序。仅使用[另编的虚构输入](../intake-cases.json)，未将个人交易、分享对话或附件收入仓库。

## 方法

四个独立代理均不继承维护者对话，每组只获得从上传 ZIP 解出的隔离技能及第一条输入。后续输入在上一轮答复完成后逐条交付，同组沿用自己的对话上下文；未提前给后续信息、预期答案、修订说明或其他组输出。技能自身的正常示例可读。

共四组九轮：一体版三轮、计划核对独立版两轮、执行复盘独立版三轮、规则卡独立版一轮。维护者复核每轮实际答复，而非采用代理自评分。[完整原始记录](0.3.4-intake.json)保留输入、答复、逐轮读取清单和上传 ZIP 摘要；隔离包与当时“材料收集”修订快照的对应上传 ZIP 逐字节一致。后续新增的用户建议处理规则不在这九轮快照中，需单独检查。

## 实际结果

| 案例 | 实际表现 | 维护者复核 |
| --- | --- | --- |
| C01 · 分轮补充提损背景 | 前两轮只复述事实、追问当时市价及管理安排；用户结束补充后才总结。用 129−122=7 核对动作当时距离，未以最高 132 代替；区分设定价差与实际成交价差 | 本轮未抢先评价、未强推减仓，也未凭事后最低 108 判定提损正确。最终肯定限定于用户自述允许的修订方式，具体信号及选价合理性仍未知 |
| C02 · 不愿继续提供材料 | 首轮询问报告依据和草案；用户说按现有材料核对后，直接作有限总结，未再要求原文或重新确认结束 | 保留“自述已写好，但未提供内容”，未写成无安排；没有把新报告存在当成变更合理的证据，也未把未执行草案当作已替代原计划 |
| C03 · 结束后又有新记录 | 首轮用户已说没有更多材料，直接总结未知；第二轮补市价时更新距离，询问还有无补充，未改成“这次做对了”；第三轮明确结束后再综合复盘 | 结束状态没有被永久沿用。新止损相对入场的 2 与当时到止损的 13 分开，未拿事后低点推定实际成交、少亏金额或决策正确 |
| C04 · 只整理本人原话 | 直接给候选提醒卡，标注 AI 整理的问题、本人原话和未采用状态 | 没有把收集结束步骤扩展为所有任务的前置确认，也未附加不存在的交易复盘 |

四组九轮中未发现本轮针对的提前评价、补一项就反转结论，或忽略用户结束补充要求的问题。用户说不愿提供、记不清时，模型保留未知，没有用追问阻止有限总结。

## 局限

收集阶段虽然只列两个编号问题，有些问题仍捆绑了多个细节；用户的回答负担仍有压缩空间。最终总结也有偏长的情况，本轮不声称已经解决所有表达问题。

本轮是明确提供技能后的少量隔离试用，没有旧版对照、统计重复、长对话压力测试或真实平台安装。没有测试截图识别、跨工具交接的实际恢复、原文检查和预案整理的全部场景；交接卡里的阶段字段只做了文件与分发检查。不能外推到所有模型稳定执行，也不证明交易效果。

构建、仓库校验、19 项标准库单元测试及 `git diff --check` 通过；一体版仍只生成一个根部入口 ZIP。0.3.4 尚未发布，未做新版 SkillHub 评分、产品上传或账号安装测试。此前记录的通用检查器 PyYAML 缺失问题未在本轮处理，本轮检查使用仓库自有工具。
