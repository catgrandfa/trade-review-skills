# 0.3.4 制卡前确认与简短模板试用

日期：2026-09-15。仅使用[虚构输入](../card-confirmation-cases.json)，不包含真实交易或分享对话。

两名全新独立代理分别读取隔离的独立技能包和一体包，不继承维护者对话，不提供预期答案。Q01 的后续输入逐轮交付，第二轮根据实际追问补充定义。维护者检查[完整实际答复、读取清单与包摘要](0.3.4-card-confirmation.json)，结果如下。

| 案例 | 实际表现 | 复核 |
| --- | --- | --- |
| Q01 第一轮 | 针对“偏离计划”“连续两笔”的范围和“停一下”的动作提出三个问题 | 没先把猜测写入规则；明确内容澄清不代表采用 |
| Q01 第二轮 | 用户补充后给出提醒、场景、两个问题与来源状态 | 只使用用户确认的动作和条件；仍为候选，保留已有仓位按原计划处理 |
| Q01 第三轮 | 用户明确采用后更新为本人已采用 | 生效时间保留“下一次练习”，范围限定模拟练习；未再次要求同一确认 |
| Q02 | 用户拒绝定义旧说法、给出明确新原话后，直接交付一张小卡 | 没再追问十分钟或等待信号，未加入未选参数；标题兼作提醒，只有一个问题和候选来源短注 |

卡片保留了默认模板所需内容，但 Q01 把“什么时候用”放在“一句提醒”之前，且条件在标题和问题中有重复。未要求逐字或固定顺序匹配；不把字符数等同于实测一屏高度。Q02 没有单独重复“一句提醒”，符合标题已表达完整时的省略规则。

两组实际试用的技能包与当轮构建中的对应上传 ZIP 相同；此后增加稳定 ID 和内容版本规则，本报告现为此前快照，未在最新包重跑。仅两案四轮，不代表所有歧义、来源或模型均已覆盖；未全量重跑此前建议及收集流程案例，未进行 WorkBuddy 等产品安装、显示或文件保存测试，也不证明交易有效性。
