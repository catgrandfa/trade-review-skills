# 0.3.3 首次使用与短答试用

日期：2026-09-15。目的：检查口语请求能否直接得到有依据的答复，以及 FAQ 是否按问题使用。不是 SkillHub TRACE 复测，不推测评分会提高多少。

## 方法与实际范围

- [六个虚构输入](../first-use-cases.json)由维护者编写，不含预期答案；与随包首次使用演示不是同一组输入，但覆盖的边界有重合。
- 六个全新独立代理不继承维护者对话，每个只收到一案输入及从上传 ZIP 解出的隔离技能。未提供预期结果、修订说明或前案答复。技能正常附带的示例仍可读，不声称隐藏了包内示范。
- N01 用一体版复盘操作，N02–N05 分别用计划、观点、预案、规则卡独立版，N06 用一体版回答用法问题。没有要求代理自评分或修改技能。
- [原始记录](0.3.3-first-use.json)保留输入、完整答复、代理报告的实际读取资源和 ZIP SHA-256。维护者确认每个隔离包与最终构建的对应上传 ZIP 逐字节一致。
- 维护者逐案对照原输入，检查第一段是否回答问题、是否填空表或先讲教程，以及来源、事件状态、条件和采用状态有没有改变。

## 实际观察

| 案例 | 输出中的证据 | 维护者判断 |
| --- | --- | --- |
| N01 · 卖出后上涨 | “仅凭后来涨到 82，还不能判定……是错误”；三段完成，只读取执行模块，保留回补安排未交代 | 正确选择执行复盘；没有把卖飞等同于执行错误，或编造原先没有预案 |
| N02 · 提损与利润 | 开头说明“目前只是打算，尚未修改，也没有成交”；以实际按 51 退出为假定解释 1 个价格单位的价差 | 没有把拟改止损写成已锁定利润，也没补净收益；四段中原止损合理性等补充仍可压缩 |
| N03 · 观点理解 | 保留“连续两个交易日收盘高于 60”及确认前先跌破 55；保留 S8；没有凭现价 61 判断历史确认 | 理解检查有依据，未强化原文为可以买；四段中重复解释了确认与取消关系，简洁性仍有改善空间 |
| N04 · 条件草案 | 列出三个分支，周五收盘严格高于 60、先跌破 55 的顺序保持；“当前属于哪个分支：未知” | 没有补买卖动作或选择当前分支；额外列了具体周五日期、时间上限未提供，未强行设定期限或阻止交付，但略增加阅读量 |
| N05 · 只做候选卡 | 直接交付一张卡；“候选，尚未采用”；临场问题标为 AI 整理，保留当时有无回补计划未知 | 没附加完整交易复盘，也没补价格、比例或次数；附带一条后续观察，仍在卡片范围内 |
| N06 · 没规则、截图和新对话 | “能开始，不必先定规则或填表”；读取 FAQ 和交接卡，没有读取交易模块；说明截图取决于平台、换对话需带上下文 | 回答了所问用法，没有要求先上传材料才能回答，也没声称已识别截图、保存或跨会话记住 |

六案均直接交付所需答复，本轮未发现事实补造、错误路由或把候选提升为已采用。N01–N05 没有读取 FAQ 或首次使用示范，也没有附加整套入门教程；N06 按所问主题使用 FAQ，没有把全份 FAQ 原样输出。这个结果支持本轮“参考按需读”的有限目标。

## 限制与未完成的验证

本轮没有旧版本或无技能对照，没有统计重复；不能证明新版比 0.3.2 更简短，也不能推断其他模型稳定遵守。观点检查和预案答复仍有可压缩的补充，不能宣称所有短答都已达到最佳长度。

这次是明确给定技能后的试用，没有测平台在众多技能中的自动发现。执行复盘通过一体版运行，未另测其独立安装版；未覆盖一体版多模块衔接、连续演示的逐轮实际运行、聊天适配或真实截图识别。作者编写的示范答复不能作为这些测试的替代证据。

没有发布、账号安装或产品内运行，没有行情验证、交易效果验证或新版 SkillHub 评分。

## 包与工具检查

仓库构建、校验、18 项标准库单元测试和 `git diff --check` 通过。检查覆盖新资源的独立分发、示范更新同步到一体版和文本适配，以及七个上传 ZIP 省略独立 LICENSE。

另尝试 skill-creator 的通用 `quick_validate.py`，当前 Python 缺少其依赖 PyYAML，未能运行；没有为此给项目增加第三方依赖。上述通过结果来自仓库自有校验器，不能写成通用检查器也通过。

## 发布前分发收敛

六案完成后，按维护者要求将一体版分发收敛为唯一的根部入口 ZIP，停止生成文件夹变体并清理本地遗留包。技能运行资源和六案所用 ZIP 的字节未变化，因此沿用上面的行为记录。最终仓库检查及 19 项单元测试通过，发布资产为六个技能上传 ZIP；上方 18 项测试与七个 ZIP 描述保留为首轮检查记录。GitHub 发布不等于已完成 SkillHub 或其他产品验证。
