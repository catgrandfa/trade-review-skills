## 试用方式与安装核验

统一输入前缀：

> 这是虚构试用：黄金是真实品种，以下价格和交易情节全部虚构，不是我的真实持仓，也没有提供实时行情。请使用已安装的 trade-review-suite 回答。问题：

每案新建任务，不向产品提供预期答案。旧版产品试用曾要求先列加载模块，本轮取消此要求；因此不能把开头或长度的全部变化归因于技能修订，也不是严格的无技能对照实验。

首轮代码来源固定为 GitHub 提交 `cf1b92c13e99b12c8f6c8e459008e97e45d446e5`。WorkBuddy 5.5.6 的用户级安装经过旧版完整备份、23 个源文件字节对照及安装器 `Unchanged` 核验。所有案例通过真实新任务输入，保留用户原有产品设置；快速模式会在模型间切换。

ChatGPT 使用 Edge 中的原生技能入口，上传从 GitHub 草稿发布下载的 `trade-review-suite.zip`，SHA-256 为 `388be43245f7d612b4bd6a05aa02f97fbf86d7c1c7a935561852f0c62b46c9be`。从“创建 → 从电脑上传”选择“替换现有技能”成功；详情页能读取新版入口和共同约定。编辑器内的“上传”会添加资源附件，不能据此认定整包已更新。

第一次六案仍引用旧版要求。随后在独立诊断轮要求产品重新读取实际资源，返回的约定原句属于旧版，与详情页不一致。再让 ChatGPT 从上述 GitHub 固定提交更新其工作环境，产品报告完整安装 23 文件、旧目录已备份、逐字节及 SHA-256 一致，实际技能读取接口回读到新版。约定文件 SHA-256 为 `1e23ff498e9e8357cb61bc2fbbeb866dc253de8667528a1fdb694e41a8a26276`。账号上传成功、工作环境更新和运行时回读是三个分别核验的步骤；不能用详情页更新单独证明运行时已换版。云端文件核验依据是产品显示的执行及回读结果，维护者没有直接访问云端文件系统。

版本差异的六案不计入新版行为表现，但没有删除其失败事实。运行时更新后，以相同问题再建六个 ChatGPT 工作任务，模型为 GPT-5.6 Sol / 轻度。

## 据此追加的修订

将“容易说过头 → 按材料改写”的具体例子放到共同约定开头，并在一体版入口提示先检查。执行模块补充成交价、清仓范围、评价措辞与三段短答要求；提损、引用和预案模块分别补充未成交状态、历史触发未知、继续观察不能缩成价位区间。新增明确例子帮助模型识别错误表达，不修改作者经验库，也不替用户选择纪律。

## 维护结论

本次确实需要优化，已经完成两次修订、独立复测及真实产品复测。具体措辞和默认交付比旧版明确，部分案例的回答更短、更准确；产品仍有未解决的过度定性，不能标为全案通过或稳定有效。

建议保留本版改进和失败记录。后续优先用相同固定文件对照不同模型与产品配置，区分运行时版本、产品附加指令和模型遵循程度，再决定改哪条指令；不要仅靠继续堆叠禁令就宣称问题已解决。下一轮也应使用新的虚构情节检查泛化，当前案例本来就是修订依据。
