# 交易行为复盘

还原当时为什么这样做，以及实际执行如何偏离或遵守计划。先读取[共同复核约定](references/review-contract.md)。没有行情实现也可复核执行，但不得声称验证了技术信号或策略优势。

先收集，等用户明确结束补充再评价。首轮先核对原判断、持仓管理安排和关键动作当时的情况；刚得到一条理由或一个新价格，不立即判定动作正确、失误或互相矛盾。下面的评价步骤仅在用户结束补充后执行。

先保留两件事：已经报告的操作，以及还没展开的当时安排。未接回不等于回补判断失败，可能条件未触发；未说明卖出比例不等于已经清仓；某段行情到达的价格不等于最终成交价。没有最终成交价、数量和成本，就不代算平均卖价或总收益。不能把“你这段没说清”写成“你自己也说不清”，也不评价用户“侥幸”“才配得上”或只因结果好才满意。

## 处理方式

1. 收集时建立简短时间线：事前可见信息与计划 → 实际操作 → 后续补充 → 结果。分别保留发生时间和记录时间。涉及提损，优先问提损时市价和当时依据，再按所问评价补产品、数量、成交或成本；不要把行情峰值当作提损时市价。
2. 用事件当时适用的规则与计划核对操作。规则后来更新，不用于追溯判定过去违规。
3. 分开评价三个维度：判断依据是否在事前说清、执行是否符合所给计划、结果实际报告了什么。未知维度保持未知。
4. 将有证据的问题分为计划内结果、判断依据不足、执行偏离、规则边界不明或操作失误。可以多类并存，不强迫归为情绪问题。
5. 给一到两个有证据的改进观察。涉及新规则时明确是候选，不因单笔结果自动改纪律。

## 避免事后重写

需要经验参照时，读取[作者经验参考库](references/author-experience.md)的 TE05–TE08、TE10–TE12。自查与模拟练习可以作为候选改进；参考次数和周期未被本人选定时，不据此判定违规或安排实盘交易。

- 晚补记录可能补充真实事前计划。本人明确说“开仓前已想清楚”时保留为事后补记的事前自述，不能说文件晚写就等于无计划。
- 后来才想到的止损或解释，记录为事后新增；不能用它证明当时已经准备充分。
- 按计划止损只支持执行评价；不证明判断一定正确，也不证明方法失效。盈利不能抵消明确的执行偏离。
- 卖出、准备回补、实际回补与剩余仓位退出分别核对。没有接回是结果，不自动证明卖出错误或事前没有预案；未提供的回补条件和未回调分支先询问，不先定为“核心错误”。清仓不自动撤销另一份回补计划。
- 收集时可以复述减半后仍有剩余仓位，不能先评价这一动作做得好。用户结束补充后，有限评价仍不能扩成“从未追价”“完全按同一标准执行”等未提供的优点。两次用了同一句理由，不证明两次采用相同判据；事实与评价都不能用事后价格替代事前依据。
- 未结束交易的浮盈与已实现结果分开；操作次数、持仓估值和账户净收益使用不同口径。资料缺失时不计算胜率或伪造统计评分。
- 周期复盘按独立事件去重；同一事件多次补记不算多笔交易。少量案例可支持观察，不足以认定稳定规律或因果关系。

## 交付

收集时简述已收到的操作与仍待展开的安排，再问一两个关键问题；首轮告知补充完后再一起复盘。用户结束补充后，先给有依据的评价，再用时间线解释，最后保留无法判断的部分。判断、执行、结果在分析中分开，普通短答不必逐项列“三维评价”。需要完整记录时用[复盘卡](templates/execution-review.md)，衔接下次计划时用[上下文交接卡](references/context-template.md)。

不要每收到一次补充就更新一版评价或规则卡。用户已经结束补充时不为缺少无关细节重新卡住总结；只对证据足够的部分作判断，其余明确保留未知。

延迟补记和盈利偏离的[示例](references/examples.md)用于检查措辞是否准确。

## 直接开始

“卖出后又涨了，帮我复盘”或“这笔赚了，执行算好吗”，都可以直接带操作记录来问。

用户问用法或边界时按需读[常见问题](references/faq.md)；想看输入和完整答复时读[首次使用示范](references/first-use.md)。已有具体任务就直接处理，不先展示教程或整张模板。
