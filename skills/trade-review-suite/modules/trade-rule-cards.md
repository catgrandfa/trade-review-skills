# 心法转规则卡

把“知道这个道理”变成临场能够核对的问题。先读取[共同复核约定](../references/review-contract.md)。规则卡用于表达和核对，不证明方法有收益。

## 处理方式

1. 还原原话和来源：个人经验、外部观点还是 AI 提议；询问或读取已有采用状态，不替本人选择观点来源或交易流派。
2. 提取这条经验想解决的具体场景、可观察线索、建议核对的问题，以及原文已有的边界与例外。
3. 写卡前，确认会改变规则含义的歧义：触发条件、动作理由或适用范围若来自 AI 推测，先用一到三个简短问题请本人确认或更正，等答复后再写入。不能一边把推测写成规则，一边在卡尾标“待确认”。确认内容是否准确与确认是否采用是两件事；“保存”“简化”都不代表其中任何一种确认。
4. 将抽象提醒转为可回答的问题。例如“别为回本交易”可以转为“如果没有上一笔亏损，我是否仍会按原依据考虑这次机会？”这是一项核对问题，不是心理诊断。
5. 未明确的比例、次数、时间、产品和执行参数保持待定义，不为“可执行”发明阈值。只追问会影响本卡含义的内容，不要求把所有参数量化；单次案例中的数字不自动成为今后的执行标准。
6. 按下方约定固定 ID、内容和版本，记录状态：观察 / 候选 / 本人已采用 / 已替代。本人明确已采用时如实记录，无需再次索取同一授权；AI 新增内容单列候选。
7. 用户要求验证或完整留档时，再说明如何观察它是否有帮助，关注能否辨认场景、能否核对执行；不把几笔盈利当成验证。普通小卡不附加一整套观察计划。

## 尊重原意与采用范围

从[作者经验参考库](../references/author-experience.md)制卡时，保留 TE/TN ID、库版本及[来源](../references/author-sources.md)。明确采用 TE 原则即可记录已采用，不重复确认；TN 数字没有单独选择就保持未选择。把本人的改写与 AI 新问题分别标出。

- 一位作者的经验不会自动适用于所有人；使用者的来源采用偏好也不是全体使用者的默认规则。
- “不要冲动”不得改成未经提供的“每次必须等三十分钟”；“少操作”不得改成“每天最多两单”。
- 偶发事件先保留为观察。使用者主动决定采用一条经验，可以记录为已采用，同时保留证据局限。
- 新版规则不改写旧版生效时间，历史交易按当时版本复核。
- 一条原话有多种解释时，先问具体歧义，不擅自选一种解释成卡。原话和范围已清楚就直接整理，不重复确认。用户不记得、不愿确认或只要按已知部分整理时，去掉争议分支，必要时只保留观察或一句提醒；不能把无答复当成同意。
- 一次交易的做法不自动成为长期规则；后一次动作的理由不能反推前一次相反的理由。计划某价位接回不等于已经挂单；复盘时补充当时理由不等于事后才想到理由。卡片、案例和来源短注都保留这些区别。
- 本人明确未选的参数写“未选择”；没有提过的参数写“未提供”。不把一种风险说成必然心理过程，不为了制卡重审整笔交易。历史细节不影响卡片原意与采用状态时，不把追问这些细节设为交付条件。

## 交付

关键歧义确认后，默认成品是一张日常能看懂、通常一屏读完的小卡，不是复盘档案。标题保留规则 ID 和版本，正文使用四项模板：一句提醒、什么时候用、问自己、状态与来源。直接给卡片，不先解释制作过程，也不在卡后再重复总结或例行询问是否采用；尚未采用就如实标候选。

- 标题说清提醒什么，正文用一句话表达核心意思。尽量沿用用户原话；“改止损前看什么”比抽象的策略或纪律术语更容易懂。
- 标题已完整表达核心提醒时，不再用“一句提醒”重复一遍。用户同时要建议和卡片时，把相关建议融入提醒或问题，不另外追加练习步骤、观察计划或说理段落。
- “什么时候看”只写一个具体场景；临场问题通常一两个，确有必要才加到三个。每个问题只问一件事，不把“价格、仓位、身份、依据、期限……”挤在同一句里。
- 卡尾用短注写清候选/已采用和来源；AI 整理的问题不要冒充本人已采用的原话。已采用规则保留生效范围，作者经验的条目与版本可放在来源短注里，不用编号铺满正文。
- 来源短注只交代出处、采用状态及必要的 AI 整理标记，不重复使用场景或整段交易背景；用户要查出处时再展开原文与解释。
- 只保留会改变这条提醒含义的边界或待定项。未决定的参数不补造，但也不打印无关的空字段清单；例如本卡未涉及仓位比例，就不追加“比例、次数、资金分母待填写”。必要的“仅供参考、不构成投资建议、以自己的实际情况为准”说明不能为缩短而删掉。
- 用户要求修订时整理一张新的当前版本，合并重复问题、移除已撤回的推断，不把每一轮讨论都追加成一条规则。按下方约定保留原版本；用户未要求，不另生成完整档案、变更日志或第二份文件。需保存时遵守共同约定，不能覆写原始叙述或历史记录。

使用[规则卡模板](../templates/rule-card.md)的日常版。用户明确要规则的完整依据、来源明细或版本记录时，才使用该模板的留档部分，或[上下文交接卡](../references/context-template.md)。这里的规则依据留档也不等于交易复盘记录；复盘保留具体交易经过和核对结果，不受小卡的长度要求限制。缩短本卡不改动已有复盘；只制卡不默认补写复盘。规则依据留档与日常小卡分开交付，不能让读懂留档成为使用小卡的前提。

见[不发明阈值与已采用规则示例](../references/trade-rule-cards-examples.md)。

## 固定编号、内容与版本

- 首次成卡就给稳定 ID；已有 ID 原样沿用，包括本人原有的命名方式。没有既有编号习惯时用 RC001、RC002 等，按当前可读规则清单中最大序号续号，已撤销或替代的编号也不复用。个人规则 ID 与 TE/TN 来源编号、本次材料索引分开。
- 同一条规则重看、换标题、简化、修订或改变采用状态，都保留 ID；独立新增规则才新建 ID。不要仅凭名称相似合并规则。用户指向旧规则但旧卡不可读时，先请其提供该卡或 ID 对应内容，不猜测旧规则或重新编号。
- ID、内容版本和正文固定对应。再次展示或保存已有卡时沿用原文，不顺手改写或补条件；只有用户要求修改、确认新内容或更正材料时才修订。同一规则正文改变则保留 ID、版本递增（v1 → v2），原版本保留。旧卡未标版本时写“版本未提供”；开始修订可明确从本次建立 v1，保留所给旧文，不冒称旧文原来就是 v1。
- 已采用规则的新内容先记为同 ID 的候选修订，不自动取代仍生效的旧版。本人明确采用新版后记录其生效范围和时间，旧版标为已替代但不回改历史；同一请求中已明确采用新内容时不重复确认。仅候选转已采用、正文未变时不增加内容版本。
- 日常卡标题紧凑显示，如“RC001 · 规则名称 · v1”，不附整张编号表。跨对话交接保留 ID、版本、正文、状态和生效范围；只有 ID 不足以恢复内容。看不到完整规则清单时，只能核对当前材料内编号，不能声称跨账户或跨会话全局唯一。
- 固定编号不等于已经写入文件或永久记住。要求保存时按已有授权位置写入并核对，修订保留可恢复的旧版本，不默认另建第二套档案；没有保存能力则交付可复制卡片并说明尚未保存。

## 直接开始

“把这次教训做成一张提醒卡”，附上原话及是否已经采用即可，不必先重做完整复盘。

用户问用法或边界时按需读[常见问题](../references/faq.md)；想看输入和完整答复时读[首次使用示范](../references/trade-rule-cards-first-use.md)。已有具体任务就直接处理，不先展示教程或整张模板。
