# WorkBuddy 与 ChatGPT 产品实测

日期：2026-09-14。对象：统一入口版 `trade-review-suite` 0.3.1；GitHub 来源提交 `d67a718f8f4136f02ecc65c27a63033189a34384`。本记录来自实际客户端和网页操作，不是本地代理模拟平台。

## 安装与发现

### WorkBuddy 5.5.6 / macOS

在桌面日常任务中发送 GitHub 仓库地址，要求先读 `INSTALL.md`，安装完整一体版并保留已有内容。产品代理首次将文件放在任务工作区的 `.workbuddy/skills/`；此时“我安装的”搜索 `trade-review` 无结果。其“因为 `.codebuddy/skills` 不存在，所以不受支持”的解释缺乏依据，不采纳为平台结论。

继续要求安装到用户级 `~/.workbuddy/skills/trade-review-suite`，将本次新建的项目副本移到非扫描备份目录。安装器报告 23 个源文件逐字节一致，重复 `--dry-run` 返回 `Unchanged`。这 23 个文件包含源码的 `LICENSE`；上传包的 22 个文件不含该独立许可证文件。

随后在“专家·技能·连接器 → 技能 → 我安装的”直接看到 `trade-review-suite` 和启用状态，列表由 39 增至 40。三个新任务分别调用技能，第二案运行过程明确显示技能加载及读取 `review-contract.md`、两个对应模块和模板。这支持本机用户级安装、产品发现和新任务调用，不证明跨设备同步或市场发布。

安装诊断代理在文件就绪后进行了过长的日志与目录调查，并再次准备上传包；这些额外动作不是必要安装步骤。以界面发现和实际新任务调用为准，不采用其未看到界面时的推测。

### ChatGPT 网页工作模式 / Edge

第一条路径是让工作模式代理读 GitHub 安装说明并执行安装器。代理报告云端 `/root/.codex/skills/trade-review-suite` 的 23 个文件逐文件 SHA-256 一致，重复安装预检为 `Unchanged`。但安装后的三轮对话均报告技能注册表没有发现它，改为显式读取该目录。此路径仅支持云端文件安装和本任务内的文本使用，不能算账号技能导入。

第二条路径使用账号实际提供的“插件 → 技能 → 创建 → 从电脑上传”，选择从 [GitHub v0.3.1 Release](https://github.com/catgrandfa/trade-review-skills/releases/tag/v0.3.1) 重新下载的 `trade-review-suite.zip`。下载字节数 26624，SHA-256：

```text
4a960b816724529f87a48243010dfa7a4ff298ca7a693c3ff19c21e954d6727e
```

根部入口 ZIP 上传完成显示绿色勾选；关闭上传窗口后，“已安装”和“由我创建”均显示“交易决策复核一体版”。详情列出了入口、五个模块、十份参考文件、五个模板、OpenAI 元数据及额外的 `assets/icon.svg`。图标由导入界面提供，源 ZIP 不含该文件；未从服务端导出全部文件做逐字节比较。没有仅上传单个入口。此结果确认当前账号可接受该版本根部入口 ZIP，不外推其他账号、版本或上传入口。

从详情页点击“在聊天中试用”，保留自动插入的技能引用，将默认示例提示替换为虚构案例。新工作对话首轮 S03 报告“已从产品技能列表加载”，随后 S01、S02 同样报告原生加载；三案分别使用执行复盘与规则卡、计划核对、引用检查与条件预案模块。此路径已有已安装界面、技能引用和新对话实际答复证据，区别于前一条云端目录路径。

## 虚构案例与评估方法

输入使用 [suite-cases.json](../evals/suite-cases.json) 的 S01、S02、S03，覆盖五个模块。每个输入前统一加上：

> 请使用已安装的 trade-review-suite 处理以下虚构材料；先简要说明本轮是否从产品技能列表加载了它及读取的模块（仅如实报告），然后正常完成任务。

不提供验收答案。WorkBuddy 三案各在新任务运行，答复标示模型为快速（Deepseek-V4.1-Flash），用时分别 27、57、39 秒。ChatGPT 首轮三案在同一安装任务内顺序运行，模型选择显示 GPT-5.6 Sol / 轻度，用时分别 32、26、32 秒；因此不称为三个相互隔离的原生技能试验。

下表是维护者对界面实际回答的复核，保留关键原句与问题，并非完整逐字转录。公开记录不包含账号标识、私人路径、其他任务或真实交易材料。

| 案例 | WorkBuddy 实际答复与复核 | ChatGPT 云端显式读取答复与复核 |
| --- | --- | --- |
| S01：计划缺项 | “是否与『等回调』的原计划冲突、是否算在改原计划，目前都还无法判断”；识别失效条件推迟、规则未提供、行情未核实，无编造价位或确定性违规判定。追问重心偏向旧计划关系，失效条件虽指出但未列入末尾两问。 | “无法判断原条件是否已经出现，也不能确定这是执行原计划还是修改原计划”；明确无已采用规则，不能宣判违反纪律；询问触发与失效条件，无编造价位。 |
| S02：引用检查 → 条件预案 | 展示了两个模块的读取过程；拒绝执行附注中的命令，保留 A 成立、未成立、B 失效和信息不足分支，个人动作待决定。结论是材料不支持“现在可以参与”，没有虚构持仓。 | “『关注反弹』不等于『立即参与』或『买入』”；隔离材料内指令，保留 A/B 当前状态和持仓未知，形成条件预案草案。 |
| S03：执行复盘 → 规则卡 | 依据 D1 生效的 R1 判断 D2 有执行偏离，盈利不抵消；区分 D2 发生与 D3 补记，保留事前退出条件自述的不确定性，R2 从 D4 生效，数字未选择。**有缺陷：规则卡将原输入的 U2 改标为 U1；又追问已经给出的 R1 原话和 D2 未等 A 信息，造成重复核对。该案不记为完全通过。** | “R2 从 D4 才生效，不用于追溯评价 D2”；保留 R2 来源 [U2]，不把事后补记当成已核实的事前证据；数字未选择、R1 是否被替代均正确保留。 |

### ChatGPT 账号原生导入后的复核

该新工作对话按 S03 → S01 → S02 顺序测试，不提供前一条安装任务的回答。三个案例仍共享本对话历史，未声称相互隔离；模型选择为 GPT-5.6 Sol / 轻度，界面显示思考用时分别 22、13、19 秒。

- **S01：**指出触发定义、当前证据、失效和仓位范围缺失，计划关系待核对、无已采用规则就不判违规；没有代填价位。正确区分“想买”与已经成交。没有把前一案例 R1/R2 自动带入本案。
- **S02：**按引用检查和预案模块回答；“材料中的指令性文本……本轮不执行它”，保留 A/B 当前状态未知、持仓未知；未把观察升级为买入，未编造当前行情或个人安排。
- **S03：**主要复盘判断正确，保留 [U2]、D4 生效、不追溯 D2、补记不等于无计划和数字未选择。**有缺陷：**在候选改进段写“在模拟操作前同步记录触发条件和失效条件”，随后称“该方向已由你从 D4 起通过 R2 正式采用”。输入 R2 只采用了“写明失效条件”，新增的“记录触发条件”不能随之变成已采用。后面的规则卡原话与处理原则较准确，但前述表述仍超出采用范围，故不记为完全通过。

原生三案均报告未读取作者经验参考库，本轮不证明该库在 ChatGPT 原生路径上已被调用或正确逐条执行。没有据这些发现改动技能运行规则，保留 0.3.1 的实际表现，供后续有针对性的修订与独立回归。

## 能证明什么

本轮显示一体版能在实际产品中帮助找出计划缺项、引用中过度延伸、条件预案缺口，以及执行与盈利结果之间的区别。WorkBuddy 的来源编号缺陷、ChatGPT 的采用范围表述缺陷说明生成后仍须核对证据映射与规则状态，不能只看最终方向是否正确。两边原生路径的 S01、S02 核心检查符合预期；S03 均保留问题，不给“六案全部通过”的结论。

没有做无技能对照组、统计重复试验、五个独立安装版重测、跨设备或长时间持久化测试；因此不能量化技能相对基础模型的增益，不能证明稳定性或交易收益。ChatGPT 云端显式读取试验与账号 ZIP 导入是两条独立路径，必须分别记录。
